Why the Same Model Got It Wrong

1

Training data has a cutoff

Agent Script was announced at TDX in April 2026, which is after Claude's training data was frozen. So when someone asks about "AgentScript," the model reaches for the closest thing it already knows — the legacy Service Cloud Agent Scripts feature, a different technology that happens to wear a similar name.

2

Confidence doesn't signal correctness

The wrong answer was well-structured and detailed, delivered with real authority. It cited specific integration points like CTI and OmniChannel, along with best practices and practical advice — all of it for the wrong technology. That's the failure mode that matters most in an enterprise setting, where AI sounds right without being right.

3

RAG alone wouldn't fix this

Even with retrieval-augmented generation, a vector database of Salesforce docs would still need the right docs in it, chunked properly, with enough surrounding context to tell two similarly-named features apart. Context engineering goes further than that. It hands the model a structured knowledge base with syntax references, patterns, validation rules, and production gotchas, so what comes back reads less like retrieval and more like someone who has actually shipped with the language.

What "Knowing" Actually Looks Like

The context-engineered Claude does more than describe Agent Script — it writes it.

What This Means for SEs

Your AI doesn't know what it doesn't know

The vanilla response didn't say "I'm not sure" or "this might be outdated." It presented the wrong technology with the same confidence it would present the right one. For SEs preparing for customer conversations, this failure mode is worse than no answer at all — it sends you into a meeting with wrong information you believe is right.

Context engineering is a skill, not a feature

This isn't about buying the right tool or picking the right model. The context-engineered Claude runs the very same model, Opus 4.6, as the vanilla one. What separates them is architecture. It's a growing set of wiki pages, memory files, skills, and validation hooks, built up over time by someone who uses AI for real work rather than demos, and it keeps getting sharper because every correction it absorbs carries into the next session.

The investment is smaller than you think

The AgentScript knowledge base wasn't built in a day. It started as a single wiki page, then a skill got added, then memory files that captured corrections and decisions, and the whole thing grew alongside real work. You don't have to build the entire architecture before it pays off — a single CLAUDE.md file carrying your org's patterns already beats the default by a wide margin.

Start With One File
